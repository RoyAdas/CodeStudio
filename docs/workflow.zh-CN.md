# v0.4 调试、测试和 AI 修改

## Python 断点调试

安装包自带固定版本 debugpy，调试不下载或安装项目依赖。项目需要 Python 3.10 或更新的 Python 3，使用“项目设置”里生效的系统解释器或虚拟环境。

1. 打开 `.py` 文件，在代码左侧断点栏点击，或按 F9 设置和移除断点。
2. 左侧选择“调试”，点击“开始 Python 调试”。开始前保存打开文件；可勾选“在程序入口暂停”。运行参数沿用终端上方的参数栏。
3. 暂停后查看调用栈、当前执行行和变量。使用继续、单步跳过、单步进入、单步跳出；运行中可以暂停或停止。
4. “请导师解释当前状态”会主动发送当前暂停位置与最多 50 个变量值。暂停不代表程序或任务已完成。自动导师在调试过程中等待，不自动发送变量。

当前仅显示工作区内调用栈和前两个非昂贵作用域的变量，不展开对象树、不执行表达式，不支持调试标准输入、条件断点或多进程。需要交互输入时使用普通运行。C/C++ 继续支持编辑、补全、诊断与运行；C/C++ 调试留待后续版本。

运行、调试、测试及环境操作互斥。调试达到设置中的运行时间上限会停止；必要时先调大上限。修改代码后需停止并重新调试，旧暂停状态对应启动时保存的代码。

## Python 测试与导师验收

左侧“测试”使用 Python 标准库 `unittest`，无需安装测试框架。默认测试目录为 `.`，文件模式为 `test*.py`。点击“保存并运行测试”，查看每个用例的通过、失败、错误、跳过和错误详情。子目录中的测试请按所用 Python 的 unittest 发现规则组织，通常添加 `__init__.py`。

测试在当前项目的 Python 环境里执行真实代码，以当前 Windows 用户权限运行。支持停止与时间上限；空测试、中止和错误不会标为通过。跳过和预期失败分别显示，不算作已验证的通过用例。

测试结果记录工作区内 Python、JSON、文本和 CSV 文件的指纹（最多 1,000 个，每个最多 2 MB），排除虚拟环境、依赖缓存和常见敏感路径。打开文件的未保存修改立即让结果过期；导师验收还会核对磁盘文件，防止其他文件已变化。外部依赖、环境变量和其他类型数据的变化无法据此完整判断，请主动重跑测试。

任务导师可在测试结束后按原有自动检查间隔检查，也可点“请导师验收测试结果”。测试失败、空结果、中止或过期时，即使模型声称通过，工作台也会阻止通过。通过测试仍不自动完成任务，导师还要检查本步骤要求，由你选择推进。

## AI 修改和测试生成

点击编辑器工具栏“AI 修改对比”，描述需要修复的问题或功能。或在测试面板点击“AI 生成测试建议”。调用你已经配置的 AI 服务；会发送前六个打开文件（含未保存内容）及当前测试结果，请先关闭无关文件。

建议包含完整文件内容，最多八个文件。差异窗口并排显示原内容与建议，勾选需要接受的文件，其他文件可以拒绝；也可全部取消。生成测试仅能建议 `test*.py` 文件。新文件只能创建在已有目录内，建议不能删除、重命名、访问敏感路径或修改未提供的现有文件。

接受前检查草稿是否已变化，变化后需重新生成。接受仅改变本机编辑草稿，按 Ctrl+S 或运行前保存才写入磁盘。现有文件可使用编辑器 Ctrl+Z；工具栏“撤销上次接受”可撤销上一批，后续有新编辑时不会覆盖它们。未保存的新文件可撤回；已经保存的新文件撤销后保留为空文件，不自动删除。

AI 生成测试不会自动运行；检查断言是否符合真实需求，再保存和执行。测试输出和调试变量可能包含私人内容；需要请求导师或 AI 时先检查这些内容。密钥、升级备份和项目文件仍遵循原有迁移方式。

## 源码准备与升级

开发者在 `npm ci` 后运行 `npm run prepare:languages` 和 `npm run prepare:debugger`，再构建。准备调试器时使用 PyPI 官方文件及固定 SHA256；安装包自带组件，启动不联网下载。debugpy 及所包含组件的许可证保留在安装包内。

停止旧版，将新包完整解压到新文件夹，在“设置 → 升级与备份”迁移旧工作台文件夹或导入加密备份。项目代码与虚拟环境继续留在原工作区。
