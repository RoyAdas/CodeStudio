# 项目环境与构建

[中文](project.zh-CN.md) · [English](project.en.md) · [返回 README](../README.md)

v0.2.0 增加“项目设置”：左侧文件列表下方点击，或在顶栏选择“项目”。配置只作用于当前工作区，保存为根目录的 `.codestudio.json`。切换文件夹会读取另一个项目的配置。

## Python 虚拟环境

先安装 Python，并在“设置 → 运行环境”确认系统 Python 可用。进入“项目设置 → Python 环境”，有三种方式：

- **自动**：默认优先使用项目内 `.venv`；目录不存在时使用系统 Python。目录存在但环境损坏时会提示修复，不会悄悄切回系统环境。
- **仅使用项目虚拟环境**：环境不存在或不可用时会提示创建。
- **使用系统 Python**：忽略项目环境，使用全局运行环境中配置或检测的 Python。

点击“保存配置并创建虚拟环境”，用本机 Python 创建指定目录。默认带 pip，创建过程使用 Python 随附的资源，不下载第三方依赖。无需执行激活脚本；F5 会直接调用环境内的解释器。整个过程上限为 180 秒，期间请等待完成再切换工作区或运行程序。

环境文件夹只能是项目根目录中的一个直接子目录，例如 `.venv`、`venv` 或 `.venv-study`。已有目录不会覆盖，创建失败的部分目录会保留供你检查。选用已有环境需包含 `pyvenv.cfg` 和 `Scripts/python.exe`。更换电脑或移动项目后应重新创建环境。

需要安装第三方包时，在你自己的终端使用该环境的 Python，例如：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

工作台不会自动执行这条命令。请不要将 `.venv` 或其他环境目录提交到 GitHub；选择自定义名字时，在项目 `.gitignore` 中排除它。

## C / C++ 多文件构建

先确认 GCC/G++ 或 Clang/Clang++ 可用。在“项目设置 → C / C++ 构建”中勾选需要一起编译的源文件，并保存。

- C 列表支持 `.c`；C++ 列表支持 `.cpp`、`.cc`、`.cxx`，也可包含 `.c`。
- F5 会保存所有打开且修改过的文件，再编译对应语言的列表。列表不为空时，当前源文件需要位于列表中。
- 列表留空时继续单文件运行。不会自动把项目内所有源文件都编译进去，其他示例入口不会误加入。
- 额外头文件目录每行一个工作区内相对路径；同目录的相对头文件引用也可直接使用。
- 默认 C11/C++17，可改选其他标准；你安装的编译器必须支持所选标准。
- 混合 C/C++ 构建时，`.c` 文件由 C 编译器编译，最后由 C++ 编译器链接；接口头文件需要按 C/C++ 规则使用 `extern "C"`。

程序构建使用临时源文件和目标文件，保留原文件名及行号诊断，完成、失败或停止后清理自己的临时文件。多文件项目在工作区根目录运行，单文件程序在源文件目录运行；相对数据文件路径应按此安排。每次源文件编译或链接上限为 30 秒。

选择 `examples/c-project` 或 `examples/cpp-project` **目录本身**作为工作区，打开入口文件按 F5，可体验随附的双文件示例。

## 配置示例

```json
{
  "version": 1,
  "python": { "mode": "auto", "venv": ".venv" },
  "build": {
    "c": ["main.c", "src/total.c"],
    "cpp": [],
    "includeDirs": ["include"],
    "cStandard": "c11",
    "cppStandard": "c++17"
  }
}
```

`version: 1` 是配置格式版本，不是软件版本。配置只接受工作区内路径，不保存 API 密钥。JSON 错误会在设置页显示并阻止运行，不会自动覆盖配置。手工编辑配置后先保存，再通过项目设置查看生效结果。

当前尚未集成 CMake、外部库链接选项、增量构建、断点调试或语言服务器。普通补全仍是关键字、片段和当前文件符号；AI 接口与实时导师继续使用原来的设置。
